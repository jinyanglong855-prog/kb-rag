# kb-rag · 本地知识库 RAG 框架（数据不出域）

面向本地 Markdown 知识库的检索增强问答框架：**嵌入全程本地推理、断网可查、语料永不出域**，检索从朴素向量一路演进到「混合检索 + 精排 + 结构路由 + GraphRAG + 上下文检索卡 + Agentic 调度」的分层管线，并以自建评测集驱动每一轮优化。已在数万语义块规模的真实语料上生产使用。

## 为什么做这个项目

企业/个人知识库问答的第一个需求几乎都是知识库：把制度、流程、项目文档变成能问答的系统。但企业数据敏感，不能调外部 API。市面方案要么数据出域、要么效果差。本项目的目标：**全程本地推理、效果可量化、可增量维护、可作为 MCP 插件接入任意 Agent**。

朴素 RAG 在真实语料上会接连撞上这些问题，每一层都对应一个解法：

| 真实问题 | 解法 |
| --- | --- |
| 定长硬切把标题与正文切开 | Markdown 感知分块（按标题层级+面包屑） |
| 纯向量抓不住关键词精确匹配 | BM25+向量混合召回（RRF 融合） |
| 交叉编码器语义精排 | 本地 reranker，"卡在哪一步"与"停在等待决策"的语义对齐 |
| 历史归档压过现行文档 | 路径权威分层加权（显式规则，非黑盒） |
| 长文档切块后重点召不回 | 上下文检索卡（LLM 通读全文产卡辅助召回） |
| 小块命中但上下文不足 | 父子分块（小块检索、父块作答） |
| 状态类问题命中旧快照 | 结构层路由（目录摘要树→整文件现读） |
| 跨项目多跳问题 | LightRAG 图谱层 |
| 口语化问题与文档措辞脱节 | 查询改写（Multi-Query + HyDE） |
| 效果改动凭感觉 | 60 题自建评测集，每轮改动跑回归 |

## 快速开始

```bash
cp .env.example .env   # 配置 KB_PATH（指向你的 Markdown 知识库根目录）与 LLM API（仅问答生成用）
uv sync
uv run kb-rag add                   # 日常入库：按文件指纹秒级增量
uv run kb-rag ingest 文件.pdf        # PDF/Word/PPT/Excel/HTML/EPUB/图片 → md 落库（docling 后端）
uv run kb-rag index                 # 全量重建（结构大改/首次；摘要树走缓存）
uv run kb-rag query "问题" --mode hybrid --rerank   # 纯检索（--mode vector/chroma 可对照）
uv run kb-rag ask "问题"            # 检索+生成：带 [n] 引用；状态类问题自动先走结构层
uv run kb-rag agent "问题"          # LLM 自主调度五层检索工具回答（打印工具轨迹）
uv run kb-rag graph-build           # LightRAG 增量建图（--full 全量；--scope 子树）
uv run kb-rag graph "问题"          # 图检索多跳问答；graph-viz 导出可视化
uv run kb-rag cards --all           # 上下文检索卡全库建卡（KB_CARDS=0 关闭）
uv run kb-rag evals                 # 跑评测集输出各层匹配率对比
uv run kb-rag manifest              # 机器可读契约（外部 Agent 接入入口）
uv run kb-rag serve                 # MCP stdio server（8 工具；KB_CALLER 定角色）
uv run kb-rag write --path "a/b.md" --from 文件.md   # 写路径唯一入口（校验+scope+审计+自动索引）
uv run kb-rag scopes                # 权限规则管理视图
uv run kb-rag audit --stats         # 审计日志消费
```

## 检索管线

```
文档（md/PDF/Office/网页）
  → Markdown 感知分块（标题层级+面包屑）
  → 父子分块（小块检索 / 父块作答）
  → 本地嵌入（Qwen3-Embedding-0.6B，1024 维，ONNX）+ BM25 双路索引
  → 增量索引（内容寻址：成本 ∝ 真实变更块；构建锁+断点续传）
检索：
  向量召回 ─┐
  BM25 ─────┼→ RRF 混合 → 权威分层加权 → 交叉编码器精排 → 单文件配额防垄断
  查询改写（Multi-Query + HyDE）─┘
  结构层路由（状态类问题 → 目录摘要树 → 整文件现读）
  GraphRAG（LightRAG：实体关系图，local/global 多跳）
  上下文检索卡（命中卡回读原文——答案永远来自原文而非 AI 转述）
生成：
  ask 层强制 [n] 引用，资料不足明说，不许猜
```

## 关键设计决策

1. **起步不引入向量数据库**：数千块规模 numpy 暴力余弦毫秒级返回，先跑通再按真实规模上 Chroma；`--mode` 保留向量直查路径做对照，两者结果一致。
2. **嵌入本地化**：fastembed + Qwen3-Embedding-0.6B（1024 维），零 API 成本、断网可查、语料不出本机；LLM 走 OpenAI 兼容接口且可指向私有部署端点（检索阶段完全不需要 LLM）。
3. **父子分块**：小块用于精准检索，命中后膨胀为同文件连续块串（父块）进上下文——小块检索、父块回答，不改切块器与嵌入输入，只在装配层生效。
4. **上下文检索卡**（Anthropic Contextual Retrieval 的文件级变体）：LLM 通读整份文件产出一张分析卡进索引，命中卡回读原文。卡片按文件 SHA-1 指纹缓存，文件没变不重生成；API 失败保留旧卡、连续失败退避跳过，绝不阻塞建索引。
5. **权威分层是显式规则**：按路径模式给乘数（状态页 ×2.0、决策页 ×1.3、原始素材 ×0.5……完整表见 `authority.py`），每条命中可回答"为什么排前面"，不做黑盒重排。
6. **结构层路由是显式意图规则**：问句结构信号（"还……吗/要不要/停了"等）命中即走目录摘要树——**误命中只多带几条状态页，漏命中才是真召回缺失**，规则宁多勿漏。状态文件全文查询时现读不落索引，天然免疫索引过期。
7. **LightRAG 整合而非自建**：按复用优先原则选型（抽实体关系/图存储/多跳检索/可视化全覆盖，MIT 协议）；图谱语料比主检索窄一档（只收活跃区），防止历史归档把过期实体关系污染进答案。doc_id 以完整相对路径为种子，避开 basename 判重互撞。
8. **评测驱动**：自建 60 题考卷（12 道人工验证金标 + 48 道合成口语题），嵌入模型选型 8 臂同场实测；任何检索规则改动必须跑 `evals` 对比基线，零回归才算过，评测口径变更要登记而非静默换尺。
9. **确定性检索**：嵌入/精排固定单线程 + BLAS 单线程钉死——多线程浮点归约顺序随进程内存状态变化，近重复语料会把微小差异放大成排名翻转，评测不可复现。修复后两次全量评测逐位一致。
10. **Agentic RAG = MCP server**：五层检索做成 schema 规范工具（8 个），供任意 MCP 宿主 Agent 调度；不引 Agent 框架，保持最小依赖。

## 实测数字

**嵌入模型选型**（自建 60 题考卷，v@5 召回）：

| 模型 | 召回率 |
| --- | --- |
| bge-small-zh（旧基线） | 40% |
| Qwen3-Embedding-0.6B（本地，现役） | 78% |
| Qwen3-8B + 指令前缀（天花板参考） | 87% |

**分层检索**（数万块真实语料，12 题人工金标集）：

| 层 | 匹配率 |
| --- | --- |
| 裸向量@5（刻意保留的对照层） | 12% |
| 混合@8（BM25+向量+权威分层） | 88% |
| 混合+精排@5 | 88% |
| + 查询改写融合@8 | **100%** |
| 结构路由（状态类问题） | 100% |

**上下文检索卡**（试点 50 卡同语料 A/B）：裸向量@5 **25% → 75%**；全库铺开后主检索层双 100%，否定语义难题（"还开着吗"vs 答案"已停止"）三层靠卡命中。

## 安全设计

- **语料永不出域**：嵌入与精排全本地；卡片生成如接 API，属构建期批量导出，企业落地可把 `LLM_BASE_URL` 指向本机 OpenAI 兼容后端。
- **fail-closed 权限层**：`scopes.json` 规则表 + `resolve(caller, kind)` 单一事实源——规则表损坏/结构非法/未知 caller 无 default，一律拒绝而非放行；显式空列表=明确无权限。
- **写入身份不可自报**：MCP 写入身份只来自进程环境 `KB_CALLER`——工具参数可被提示注入伪造，环境变量归宿主管（一个 MCP 实例=一个角色）。
- **读路径检查顺序**：路径形状 → scope → 存在性——越权者无法用报错差异探测文件是否存在；`../` 穿越拒绝、语料装载跳过符号链接（防索引投毒）。
- **失败也留痕**：写失败、工具异常、读拒绝统一进审计 JSONL；受限角色不触发自动重建（防诱导 DoS）。

## 已知边界

- CLI 的 `wiki`/`graph` 命令不做 caller 过滤（本机 CLI 视为操作者自身，信任边界在进程身份）；审计无哈希链防篡改。
- 卡片生成依赖 LLM API（可关闭 `KB_CARDS=0`；关闭后存量卡随文件变更自然衰减）。
- 图谱层按角色过滤未支持：受限角色图查询明确拒绝，不静默泄漏。
